# 🍃 云栖茶园 · 坡地地块认养全栈主题站

一个从零搭建（无前端框架、无外部地图/对象存储服务）的茶园认养演示系统。核心解决
**“会变化的山坡边界”与“固定时段的认养承诺”如何对齐、且不被重复分配**的问题。

## 运行

```bash
npm install      # 仅依赖 better-sqlite3（已随仓库预装则可跳过）
npm run seed     # 初始化 SQLite + 演示数据（含拆分/合并/纠偏、未决差异、送礼链接）
npm start        # http://localhost:3000
npm test         # 40 个自动化测试（几何/服务/HTTP 端到端）
```

演示账号：

| 角色 | 用户名 | 口令 | 能力 |
|---|---|---|---|
| 管理员 | `admin` | `tea-admin-2026` | 全部读写 |
| 运营 | `staff` | `tea-staff-2026` | 只读 |

种子会在控制台打印两条送礼链接 token（一条 15 天有效、一条已过期），
拼成 `http://localhost:3000/gift.html?gift=<token>` 即可体验独立送礼视图。

## 页面

- `/` 山坡 SVG 地图（拖动/缩放、**日期时间轴回放**、点地块看版本与认养时段）
- `/diaries.html` 生长日记（**离线**写入 IndexedDB 队列，联网幂等同步）
- `/tests.html` 检测公示（每条结论只对**声明采样范围**有效）
- `/admin.html` 后台：地块拆分/纠偏、认养区间、未决差异裁决、采摘/采样批、附件撤回、送礼链接
- `/gift.html?gift=...` **独立权限**的送礼只读视图
- `/design.html` 原创设计说明

## 关键设计如何对应需求

1. **空间数据库保存地块版本**：`plot_versions` 只增不改，拆分/合并/纠偏都生成新版本并写
   `plot_events` 血缘与 valid_from/valid_to；地图按日期做时间点查询。
2. **拆分/合并不重复分配**：认养锚定创建时的边界版本。边界事件后建立
   `area_correspondences` 面积对应；超卖检查沿**地块血缘**汇总“本地块认养 +
   祖先认养按原边界保留的份额（含未决差异）”，超出当日边界面积即 **409**。
3. **旧认养按原边界保留，新边界建立面积对应与未决差异**：
   `fixed` 旧记录面积/价格不变，新边界只建对应，差额进入未决清单；
   `redistribute` 按几何交集比例自动迁移，旧记录 `migrated` 归档。
4. **采样批只代表声明范围**：必须填 `scope_claim` 并锚定采样日边界版本，
   全站统一“仅代表该范围、不代表整园”文案。
5. **对象层归档检测附件**：文件在 `data/objects`，元数据入库；撤回逻辑+物理删除，下载 **410 Gone**。
6. **送礼独立权限**：独立 `X-Gift-Token`（过期/吊销/次数上限），与登录会话分离；
   **价格、认养人、联系方式在服务端 DTO 即被删除**，不是 CSS 隐藏（测试对响应原文断言）。
7. **版本条件提交与并发占用**：纠偏带 `expected_version_id`（过期 **409**），
   编辑器对版本加租约锁（他人持锁 **423**）。
8. **离线日记**：client_uuid 唯一约束做幂等 upsert；Service Worker 只缓存外壳、
   绝不缓存 API/附件，保证撤回与过期实时生效。

## 结构

```
src/
  schema.sql         表结构（版本/认养/面积对应/采样批/附件/送礼/锁…）
  geometry.js        自研平面几何（面积/三角化/裁剪/拆分/共边缝合）
  plotService.js     空间版本化、拆分合并纠偏、血缘追溯、占用锁
  adoptionService.js 认养区间、份额策略、跨版本超卖校验
  farmService.js     农户/日记/采摘/采样/对象层附件/送礼视图
  auth.js server.js  会话与送礼双权限、HTTP 路由
public/              原生 ES Module + SVG 前端（无构建）
tests/               node:test（geometry / spatial / farm / http）
```
